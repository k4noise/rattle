# Rattle

Разрабатываемый сервис для проверки HTTP API некорректными запросами по OpenAPI-схеме. При ошибке целевого сервера сервис старается уменьшить упавший запрос до короткого воспроизводимого примера, который всё ещё вызывает падение.

**Сейчас реализован парсер OpenAPI.** Генератор запросов, отправка HTTP запросов, минимизация и REST API — следующие этапы, а не уже работающие возможности.

## Парсер OpenAPI

`OpenAPIParser.parse(raw_spec: str | bytes) -> OpenAPISpec` принимает JSON или YAML; байты декодируются как UTF-8. Экземпляр можно использовать многократно, в том числе после ошибки входных данных. У каждого эндпоинта в `spec.endpoints` есть `method` и `path`.

### Поддерживаемое подмножество

- OpenAPI `3.0.x` и `3.1.x`; операции `GET`, `POST`, `PUT`, `PATCH`, `DELETE`.
- Параметры `path`, `query`, `header`, `cookie`; параметры операции переопределяют параметры пути. Имена HTTP-заголовков сравниваются без учёта регистра. Определения header-параметров `Accept`, `Content-Type`, `Authorization` игнорируются с предупреждением, как предписывает OpenAPI; схемы авторизации пока не обрабатываются.
- Тело `application/json` и `application/*+json`. Если указано несколько вариантов, обычный JSON предпочтительнее.
- Локальные `$ref` на объекты внутри документа, в том числе в `components/schemas`, `parameters` и `requestBodies`. JSON Pointer поддерживает экранирование `~0` и `~1`.
- Объекты, массивы и примитивы; извлечение `enum`, `required`, `minimum`/`maximum`, `minLength`/`maxLength`, `pattern` и `format`. Целые числовые границы не преобразуются во `float` и не теряют точность.
- `nullable`, пара типов `[T, "null"]`, `anyOf` из одного типа и `null`, одиночная обёртка `allOf`.

Это **извлекатель данных для фаззинга, а не полный валидатор OpenAPI**: он проверяет используемые структуры, но, например, не требует `info.version` и не валидирует `responses`. У path-параметра пропущенное `required` нормализуется в `True`; явно заданное `False` считается ошибкой.

### Ограничения и ошибки

- `HEAD`, `OPTIONS`, `TRACE` пропускаются; не-JSON тело не включается в модель запроса. Об этом возвращаются сообщения в `spec.warnings`. Если поддерживаемых операций нет, разбор завершается ошибкой.
- Внешние ссылки, boolean-схемы, общий `oneOf`/`anyOf`, несколько ветвей `allOf`, другие объединения типов и неподдерживаемые ограничения вроде `additionalProperties` приводят к `InvalidOpenAPISpecError`. Они не превращаются молча в неограниченный тип `any`.
- Дополнительные ограничения рядом с `$ref` или поддерживаемой композиционной обёрткой тоже отклоняются, а не теряются при раскрытии.
- Описательные аннотации, `default`, примеры, `readOnly`/`writeOnly` и расширения `x-*` не влияют на генерацию модели. `pattern`/`format` сохраняются, но не исполняются и не проверяют значения на этом этапе.
- Рекурсивное поле помечается `SchemaSpec(is_recursive=True)`. Цикл чистых алиасов (`A -> B -> A`) считается ошибкой. Повторное использование одной схемы в соседних полях циклом не является.
- Глубина схемы и длина цепочки ссылок ограничены 64 уровнями, общий бюджет — 10 000 посещений схем на документ. Это ограничивает раскрытие вложенности, YAML-циклов и разветвлённых графов `$ref`.


## Уточнения парсера

- Загрузка использует правила YAML 1.2 Core и отклоняет дубли ключей и не-JSON значения. Значения `enum` копируются по вхождениям; глубина и число раскрытий ограничены, циклы отклоняются.

## Планируемые критерии падения целевого API

- Ответ со статусом `5xx` или обрыв соединения во время ответа, когда сам сервер работает.
- Ответы `4xx` падением не считаются, потому что так API отклоняет неверные данные.
- Если целевой сервер перестаёт отвечать на несколько запросов подряд, проверка останавливается с сетевой ошибкой и не записывает это как падение API.

## Планируемые REST-эндпоинты

- `POST /jobs` — запустить проверку
- `GET /jobs/{id}` — статус и прогресс проверки
- `GET /jobs/{id}/crashes` — список найденных падений
- `DELETE /jobs/{id}` — остановить и удалить проверку
- `GET /docs` — Swagger UI

## Выбор коллекций

- `list` — упорядоченные накопления: эндпоинты, параметры и предупреждения при разборе; позже — падения и шаги уменьшения запроса.
- `tuple` — неизменяемые ключи для `set` и `dict`: параметра `(имя, расположение)` при объединении; позже — ошибки `(метод, путь, код ответа)`.
- `dict` — исходный документ, свойства JSON-объектов, объединённые параметры; позже — хранение проверок по `id`.
- `set` — дубликаты параметров и циклы `$ref`; позже — отсеивание повторных падений по ключу ошибки. `frozenset` — обязательные поля и путь активных ссылок в рекурсии.
